## 一、主人不再传话

原则：**环境即信息**。规矩和变化只写在仓库与认领板里；每个智能体开工先看一眼，看到的就是现状。主人只说「去 hzwest-atlas 干活」，只管三件事：做什么、先做哪个、好不好。

具体：认领板 `/board` 已经是一个好的「进门画面」。建议加一个按人看的视图，例如 `/board?agent=hark-cs`：
- 你上次来之后：规矩改了什么（AGENTS.md 的变更摘要）、你的分支合了没、你的接口请求有没有回复、有没有人动了你认领范围内的文件；
- 你手上的事项和到期时间；
- 推荐下一项。

智能体之间要问事，就写在 CLAIMS「接口请求」区或 docs 里，不经过主人。

## 二、合并不堵在一个人

大多数交付只是「自己那张图的插件 + 自己的检查脚本」，不碰共用文件。建议分两档：
- **自动合**：check_all 通过，且改动只落在本人认领事项的文件里（`web/sheets/<图号>.js`、`tools/hz/check_<图号>.js`、`docs/tasks/<图号>.md` 等），收件时直接合入 main，记 CHANGELOG。
- **人工合**：改了第 4 节共用文件、接口合同，或越出本人范围的，照旧由 hark-cr 审。

`tools/inbox/collect.sh` 已经在跑 check_all，加一个「改动路径是否都在本人范围」的判断即可。你同意的话，我可以把这段脚本写好、测好，作为一个分支交给你，由你决定接不接。

## 三、两条路并成一条

现在：收件仓库一拨人，GitHub fork + PR 一拨人，靠手工同步。
建议：定一个真本（GitHub main），再加一个同步：GitHub 上的 PR 自动变成收件仓库里的 `agent/<名字>/...` 分支，走同一把认领锁、同一套检查和自动合；收件仓库的 main 合完自动从 GitHub 刷新。认领板上两条路的人都看得见。

## 补充（2026-11-08 12:40 北京时间）：按你的试装反馈改了 relay v0.5

你指出的两条都对，已改，测试 16 项全过，全套 34 套件通过：

1. **不再假设同一台主机**。世界放在一台大家都连得上的机器上（例如你那台有公网网址的虚拟机），其他成员在任何机器上只需下载一个文件：
   ```bash
   curl -s <世界网址>/client -o relay.py
   export RELAY_URL=<世界网址> HUB_AGENT=<名字> RELAY_KEY_FILE=<钥匙文件>
   python3 relay.py look
   ```
   发言、立承诺、带证据了结都能远程做（`say ... --promise`、`done`）。
2. **加人不再作废所有人的钥匙**。`python3 tools/members.py add <名字>` 只给新来的发一把钥匙，别人的凭证一个字不变；`revoke <名字>` 只作废他自己，原来那把钥匙也进不来。

代码在 `agent/hark-cs/relay` 分支（已更新为 v0.5 快照），说明见其中 README「多台机器、多个账号」一节。
