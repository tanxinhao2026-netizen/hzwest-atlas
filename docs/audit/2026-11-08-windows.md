## 问题单

### P2-1 根地址带 `#sheet=` 会被跳转丢掉图号，永远落到 S-000

- 图号：全部（入口问题，与具体图纸无关）
- 视口 / 时刻：1920×1080 · 打开即发生
- 现象：打开 `https://changrong996-droid.github.io/hzwest-atlas/#sheet=S-501`，落到 `.../web/hzwest.html`，`window.__pv.sheet === 'S-000'`，看到的是总图而不是 S-501。`index.html` 只有一行 `<meta http-equiv="refresh" content="0; url=web/hzwest.html">`，跳转目标不带 query / hash。
- 复现：Chrome、Edge 稳定复现；直接访问 `web/hzwest.html#sheet=S-501` 正常（`sheet=S-501`，四张插件图纸 `S-101/S-201/S-401/S-501` 全部登记成功，`plugCount=4`）。
- 影响：对外分享「某一张图」的短链接失效，委托人点开永远是总图。
- 建议（不由本次改动）：`index.html` 用脚本把 fragment 带过去，如 `location.replace('web/hzwest.html' + location.hash)`；或首页直接做成 `hzwest.html` 的入口。
- 取证：DOM 值 `{href: ".../web/hzwest.html", sheet: "S-000", plugs: 4}`

### P2-2 冷启动到 `ready` 5.2–9.9 s，默认走 unpkg CDN 明显慢于本地 three

- 图号：全部（首屏问题）
- 视口 / 时刻：1920×1080 · 首次访问、禁缓存
- 现象：默认链接从 `goto` 到 `__pv.ready` 两次测得 7983 ms / 9911 ms（`load` 与 `domContentLoaded` 均 3909 ms）；同条件改走仓库内副本（`&three=local`，`web/vendor/three.module.js`）为 5207 ms。资源 14 个、传输合计 182.9 KB，瓶颈在 `https://unpkg.com/three@0.160.0/` 这一段外网。
- 复现：禁用缓存稳定复现；缓存命中后二次打开无此延迟。
- 影响：网络受限或境外 CDN 抖动时首屏白等 5–10 s，观感接近「打不开」，离线演示不可用。
- 建议（不由本次改动）：默认改走 `vendor/`，或 CDN 失败自动回退本地；`web/hzview.js` 第 6 行 `THREE_BASE` 与第 77–80 行的 `three=local` 开关已是现成的，改动很小。
- 取证：`load=3919 ms · ready=7983 ms`（另一次 `ready=9911 ms`）；对照 `three=local ready=5207 ms`

### P3-1 冷启动偶发 12 条 WebGL 警告

- 图号：S-501 · 1920×1080 · 首帧前后
- 现象：`[.WebGL-0x…] GL_INVALID_VALUE: glGetProgramiv: Program object expected.` 连续 12 条；同机另两轮 Chrome 冷启动与一轮 Edge 均为 0 条，**不稳定复现**。
- 影响：无可见影响——该轮三时刻覆盖率、帧率、报错计数都正常，判断是着色器程序尚未 link 完成就调用 `glGetProgramiv` 的时序告警。
- 建议：留档观察，二稿动 `look.js` / `fx.js` 时顺带排查。
- 截图：`s501-1920x1080-begin.png`（该轮无警告，作对照）

### P3-2 末段墨线转实景时 3D 覆盖率骤降到 0.230

- 图号：S-501 · 1920×1080 · `t≈1085`（距 `OPEN=1101` 约 16 天）
- 现象：20 帧扫掠里其余帧为 0.28–0.99，唯独这一帧降到 0.230：墨线已大幅淡出、实景还没接上，过渡中有一帧偏「空」。
- 影响：单帧过渡，实时播放几乎看不出；逐帧导出或慢放能看到。
- 建议：请集成人确认是否为 `blend` 曲线的预期过渡；若不可接受，把淡出与实景接续的重叠区间加宽。
- 截图：`s501-1920x1080-open.png`

### P3-3 `body.splug` 模式下 `#ttl` / `#nums` 被隐藏，读数只剩左上大数字块

- 图号：S-501（其他插件图纸同机制）· 1920×1080 · 全部时刻
- 现象：页面 `body` class 为 `splug ready` 时，`#ttl`（总标题「杭州西站 · 施工推演 2019–2022 · 规则推出顺序 · 自动出图」）与 `#nums`（施工天数 / 屋盖高度 / 网架杆件数）计算样式为 `display:none`、`#hud` 高度 0，可见数字只剩 `#big`（起 262×134、末 424×134；纸色底深字对比度 15.1:1，末段转深底浅字，均可读）。
- 判断：与委托人「一屏看完、少数字、一张图一个大数字」的口径一致，倾向是有意为之；但若原设想是保留右侧读数，这里就是缺失。
- 建议：请集成人确认是设计取舍还是布局漏配；本次不改。
- 截图：`s501-1920x1080-begin.png` / `-mid.png` / `-end.png`
